# Drawer Lumber Planner — Project context

This is a compact, browser-based lumber estimator developed alongside a custom kitchen cabinetry project. Preserve both the user's drawer data and the existing feature set across revisions.

## Calculator requirements
- Group drawer configurations by drawer-box height. Each group contains multiple rows with quantity, **outside** drawer-box width, and front-to-back depth.
- Compact UI: one set of column headers per height group, no duplicated row labels.
- Default nominal purchased stock: 4/4 maple (1 inch), final machined thickness: approximately 1/2 inch. The theoretical board-foot figure uses purchased nominal thickness, not final thickness.
- Estimate theoretical material for four drawer sides per drawer. Applied decorative fronts and bottoms are excluded.
- Estimate purchased board feet using purchased board width, thickness, saw kerf, edge trimming, width allowance, length allowance for planer snipe, and per-BF price.
- User prefers to manage their **33% spare stock margin separately**; optional margin field defaults to zero.
- Yield estimate is approximate; a future revision may pack actual parts into specific lengths of stock more intelligently.
- Save all user inputs in localStorage using `drawer-lumber-planner-v1` for compatibility with existing versions. Do not rename or reset without migration.
- Retain JSON project export/import and CSV export/import. Validate imports. Preserve schema compatibility with previous project files.
- Iterative changes should update `index.html` in this GitHub repo and not require the user to download new HTML files.

## Woodworking design context
- Approximately 24 drawer boxes for inset kitchen cabinetry, with applied, adjustable decorative fronts.
- Drawer boxes will be approximately 1/2-inch solid maple, through-dovetailed using a Leigh D4R Pro. Asymmetric decorative Fibonacci-inspired tail proportions: 1:2:3 for small/medium drawer sides and 1:2:3:5 for taller bottom drawers, smallest at bottom.
- Drawers range from roughly 5-inch tall top drawers to approximately 11-inch tall deep drawers. Exact quantities/dimensions belong to the user's calculator project data, not assumed examples.
- Sources maple at Crosscut Hardwood, Seattle. Considering 4/4 S2S and approximately 7–9-inch wide boards, edge-gluing when needed.
- Rough crosscuts include extra length to remove leading/trailing planer snipe (the machine showed approximately 3 inches at each end). Purchased boards may be 8–10 feet long.
- Milling: stage rough-mill (around 5/8-inch or as thick as possible while flat), let rest 48–72 hours, then dimension to around 0.510–0.515 and drum-sand to final 0.500 inches, typically 150 grit.
- Machines: JET JPJ-12B jointer/planer and JWDS-1632 drum sander. The latter has a known snipe tendency and needs alignment checks. User has limited shop floor space and wheels machines in and out as needed.
- Basement and kitchen currently have similar relative humidity (~51–52%), so maple can acclimate in basement.
- Finish plan: Rubio Monocoat Oil Plus 2C for maple drawer boxes/pull-outs. Separately considering Waterlox Original for future Boos maple butcher-block countertops, applied outdoors in spring/summer.
- Painted inset decorative faces and face frames: unfinished reveal target approximately 3/32 inch; finish will slightly reduce it.
- Other cabinetry includes custom spice-rack and trash pull-outs, roughly 12-inch width and 10-inch depth, with Salice slides. Not included in drawer material totals unless later requested.
- Future finishing: waterborne cabinet paint sprayed in temporary ZipWall-isolated basement section with window ventilation, investigating HVLP versus Graco Magnum.
- Preserve conversation/project context in this file as decisions evolve. Prefer not to silently rewrite established woodworking assumptions.

## Edge-glued tall parts (v1.6)
When a drawer side's height plus machining width allowance exceeds usable purchased board width, estimate an edge-glued panel assembled from the minimum number of strips. For example, an 11-inch-high side from 8-inch stock uses two strips. This is conservative because offcuts from the narrower component are not credited against other drawer parts. The total extra length per individual cut part is applied once (e.g., 6 inches combined for both ends), not twice.

## Whole-board estimates (v1.7)
The calculator now accepts nominal purchased board length in feet (default 8). It builds a cut list for every drawer front/back and two sides, adds total end-snipe allowance once per physical part, splits oversized drawer heights into edge-glued strips, and uses a deterministic free-rectangle packing heuristic across finite stock lengths and widths. The displayed count is whole purchased boards; purchased BF and cost derive from that count, stock width, thickness, length, and price. The optional safety percentage rounds up to whole boards and remains zero by default. This is a heuristic and should not be represented as an exact optimal cutting plan. JSON project settings merge with defaults, so previous projects without boardLength default to 8 feet. The storage key stays unchanged.

## Drawer previews (v1.8)
The app renders an isometric-style SVG preview card for each drawer record at the bottom of the page. Previews show the open-top structural drawer box, scaled proportionally from outside width, depth and group height, and show the record's label and quantity. They update live on dimension or label edits. No new saved schema fields are required. Future iterations may show dovetail geometry, applied fronts or alternate views if requested.

## Initial rough-cut list (v1.9)
The app now includes a rough-cut list before the isometric previews, for crosscutting oversized blanks *before* the initial acclimation period. It lists rows for each drawer record's front/back and sides with the drawer label, height group, number of physical blanks, rough lengths, rough widths, and whether the part requires edge-gluing multiple strips. Rough length is the entered outside width (front/back) or depth (sides), plus the total per-piece snipe allowance, once. Rough width is the drawer height plus extra width allowance, divided across strips if the panel won't fit across the selected usable purchased stock width. An independent cut-list CSV export is provided. This is a rough blank schedule, not a definitive joinery cut plan; glue-up edge jointing loss is not separately modeled, and board-level kerf is accounted for by the purchasing estimate rather than the blank sizes. Saved drawer data schema and storage key remain unchanged.

## Initial crosscut list (v2.0)
The former rough-cut list has been simplified to an **initial crosscut list** for full-width purchased boards before acclimation. It aggregates identical oversized crosscut lengths, with quantity and drawer/part provenance; no rough widths or construction columns. Each length is outside drawer width (front/back) or drawer depth (sides), plus the total end-snipe allowance once. For tall panels needing edge-glued strips from narrower purchased boards, each strip requires a crosscut blank, so quantity is multiplied by the number of strips; ripping/jointing/gluing happen later. CSV export follows this simple list. All saved drawer data remains unchanged.

## Switchable lumber profiles (v2.2)
The planner offers 4/4 S2S (one usable milled layer per purchased plank) and 8/4 rough (assumed two usable resawn layers per purchased plank), with independently editable prices per board foot. The existing 4/4 price migrates from legacy settings.price to settings.price4, and the 8/4 default is editable. Physical 8/4 purchases are estimated from the previous 4/4-equivalent 2D cut packing: ceil(equivalent boards / 2 * (1 + margin%)); purchased board feet use nominal 2-inch 8/4 thickness versus nominal 1-inch 4/4. This is a planning approximation: two resawn usable layers must actually be feasible after blade kerf, twist and flattening, and packing two distinct layers into each purchased plank may not be optimal. The initial crosscut list in 8/4 counts physical thick crosscut blanks (ceil aggregated thin-layer requirements / 2 for each length), to be resawn after crosscutting. Existing drawer data / localStorage key unchanged. The theoretical material metric remains the nominal 4/4-equivalent volume (does not double in 8/4 mode).

## Reload and settings UI (v2.3)
Settings controls are reconstructed whenever the drawer list is rendered, including initial startup and structural edits; a browser bfcache pageshow handler re-reads saved localStorage state and re-renders on a restored page. The persistent storage key, labels, groups, pricing profiles, and existing project file format remain unchanged. This addresses reports of missing assumptions controls and stale drawer state until a profile switch. Confirm behavior in the hosted browser if these symptoms recur.

## Per-drawer vertical construction (v2.5)
Each drawer row has a Vertical checkbox (default false, remains backward compatible). Vertical is intended for tall pull-outs such as trash cubby and spice rack: it models two upright front/back maple panels only, without top, bottom or side panels. Previews show two upright separated panels, and vertical glue-up seams (grain/board lengths run upright), determined by whether the entered drawer width exceeds usable stock width. Unlike ordinary drawers, a vertical part's crosscut length is the height-group dimension plus end allowance; its glue-up width is the entered drawer width plus width allowance. The material estimate and initial crosscut list include only those two panels, with resaw yield per selected stock profile. Vertical flag survives JSON export/import, CSV export/import, and autosaved localStorage. Future enhancements may model structural rails and plywood floors separately.

## Vertical drawer dimensions (v2.7)
For vertical drawers, the row Width is the upright panel height (the crosscut dimension, plus end/snipe allowance). The height-group dimension is the horizontal panel width (and determines the number of edge-glued vertical strips, if needed). Depth is used only to visually separate the two upright front/back surfaces in the SVG preview; it does not contribute to material volume, cut quantity, costs or length. Depth is still editable and saved. Regular drawers use the original dimensions unchanged.

## 6/4 SAB profile (v2.8)
Added a third purchased-lumber profile, `sab6`, named 6/4 SAB hard maple, one usable milled layer per plank, nominal purchased thickness of 1.5 inches, and its own independently saved `price6` ($/BF). Shares board width, length, milling allowances and drawer specifications with 4/4 and 8/4 modes. Purchase board footage is 1.5x a same-number-of-boards 4/4 purchase; crosscut blank counts stay at one-layer quantities. The app must not assume 6/4 yields two 5/8-inch finished layers. Existing localStorage and project JSON remain compatible.

## Measured board cut-stock solver (v3.1)
The project has a measured inventory `state.inventory` array of board objects `{id,label,width,length}` in inches. Default inventory is empty; the persistent localStorage key remains `drawer-lumber-planner-v1`. JSON exports/imports include inventory, and older projects without inventory load as an empty array. Drawer specifications and all previous lumber profiles remain unchanged. Width and length are measured physical stock dimensions; the inventory nominal BF metric is 4/4 equivalent and assumes this batch is 4/4 SAB, independently of the old stock-purchasing profile estimator.

`solver.js` exposes `window.DrawerSolver.solve(state)` (also usable in tests). The solver expands each drawer configuration into individual physical front/back/left/right panels (vertical pullouts use only front/back). Each demand includes a stable part identifier `drawerItemId:copy:role`, required rough crosscut length including the existing end/snipe allowance, and required rough panel width equal to height-group dimension plus milling allowance. Vertical drawer row Width is the upright panel length; Depth is preview separation only.

Heuristic assignment processes wider panels first and prioritizes complete **single-piece panels**, choosing boards that let the most equal-length panels share a full-width crosscut through later ripping. If panels cannot fit single piece, the solver attempts completed glue-ups from remaining board blanks and only commits the glue-up if all its strips fit in stock. It accounts for crosscut saw kerf and total board edge trim, uses measured lengths, and reports unallocated physical panels. Plans represent full-width board crosscuts first; narrower lanes marked with dashed lines are proposed later rip assignments, not additional initial crosscuts. It is an approximate deterministic allocation, not a globally optimal nesting algorithm; grain, defects, stress after cutting, and edge-glue jointing loss are not modeled.

The solver section renders each entered board at common length scale, with stock width proportional to measured width and crosscuts at their assigned lengths. Each cut lane is individually linked on hover/focus to the corresponding front, back, left or right surface in the drawer preview; the normally hidden left wall is shown as a highlighted outline. The drawer previews take glue seam positions from the actual solver assignments whenever measured inventory exists; without inventory they retain legacy assumed-width seam rendering. A measured-plan CSV export contains board labels, start positions, cut numbers, lengths, lane widths, and remaining unassigned panels. Board inventory persists and is included in JSON project backups, while legacy generic-stock crosscut estimates and their export remain available.

Browser regression tests cover allocation, hover correspondence, persistence, incomplete glue-ups, vertical dimensions, and seam accuracy. The user has purchased about 65 BF of **4/4 SAB hard maple at $7.85/BF**, with mixed nominal 6-inch and 12-inch widths; individual board dimensions are not yet recorded in the app and should not be fabricated.

## Fixed 4/4 SAB material (v3.2)
The user has purchased 65 BF of mixed-width 4/4 SAB hard maple at $7.85 per BF and is no longer comparing lumber profiles. The app has removed 4/4 S2S, 6/4 SAB and 8/4 rough profile selector; all generic cost / board count estimates now assume exactly **4/4 SAB hard maple at nominal one-inch board-foot thickness, one layer per plank**, with a single user-editable `price4` field labeled "4/4 SAB price ($/BF)". Default price is $7.85/BF. Saved drawers and measured inventory remain in the same localStorage key and import/export schema, including backwards compatible settings; obsolete profile fields can remain in old JSON without influencing calculations. Legacy custom price4 values are retained. Inventory solver consumes actual measured board dimensions rather than nominal stock widths; original generic estimate remains supplementary.

## Minimum glue-up strip width (v3.4)
Added an editable `minGlueWidth` assumption in inches, default 2.0, named "Minimum glue-up strip width (in)". The measured-board cut-stock solver enforces the minimum for **every** glued strip, including the final remainder. If no complete glue-up meets the minimum using the available full-width crosscuts, the panel remains unassigned; never consume material on an incomplete glue-up. Single-piece panels remain unaffected. The solver prefers the least excess-width feasible two-strip combination to avoid consuming two wide blanks needlessly. Previous saved projects acquire the default via settings merge; existing drawer and board inventory data is preserved. Browser tests cover minimum widths, migration and persistence. The generic-stock estimate has evenly divided strips and is not constrained independently by this setting.

## Calculation caution
The first implementations estimate strip yield per height group and use a simplified average length calculation; they do not optimize crosscuts on finite 8–10 foot purchased boards. Check the per-part extra-length convention carefully before relying on purchasing totals. Consider a unit-tested cut optimizer as a future improvement.
